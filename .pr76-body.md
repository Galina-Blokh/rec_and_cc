## What
- macOS menu: "Recent transcripts → Name speakers…" (pick a session, pick a `Speaker N`, type a name) and a top-level "Forget all voices…" with a confirmation dialog.
- `Controller.speakers_async / name_speaker_async / forget_voices_async` run on worker threads and post `speakers` / `named` / `forgot` events; dialogs are osascript on worker threads, notifications on the main-thread timer.
- Naming calls `voices.name_speaker` (same as `recandcc name-speaker`); forgetting calls `voices.delete_all_profiles` (same as `voices delete --all`, which also cleans stored sessions).
- "Name speakers…" is greyed out unless `transcription.speaker_names` is on, and the controller refuses naming when it is off. "Forget all voices…" stays available either way, so data can be deleted after opting out.
- Hint: the speaker's first lines are shown, not an audio sample (the session WAVs are not tied to diarization turns cheaply; left for a follow-up).
- Windows tray: not added. The tray has no dialog pattern beyond the Tk search window, so this needs its own small window; noted in the story as "not yet".

## AI review findings addressed
Cursor (all rounds) and an independent Claude (Opus) review:
- Forget vs in-flight naming; overlapping namings; dropped result event; stacked `speakers` events; multiline hints; names in notices/logs: one lock per concern, `NAMING_LOCK` for namings, always-posted events, name-free notices, whitespace-collapsed hints, caplog test.
- Forget vs in-flight diarization (also profile names, `_relabel_later`): a forget generation, now persisted in `voices/generation` and checked under an OS file lock (fcntl / msvcrt), so the CLI's `voices delete --all` also stops the app's diarization; stale runs write no voices and match no names.
- `_naming_open` cleared too early / silent drop / stacked osascript: lock-protected, cleared on the `named` event or any cancel (try/finally), "Naming already in progress" notice.
- `atomic_write`: PermissionError retry with backoff, cleanup that cannot mask the error, unique temp names, `tries=1` on the live worker (never sleeps there).
- `name_speaker` held a lock over cloud-synced transcript writes: it now holds the voice lock only around voice-store steps; forget never waits on the transcript folder.
- Slow relabel overwriting a user-given name: `_relabel_later` holds `NAMING_LOCK` and keeps the transcript if a speaker of the session was already named.
- Forget on Windows with busy files: each file is retried, deletion continues after a failure, and only what is left is reported.
- Dialog scripts are built by tested helpers (`chooser_script`, `name_dialog_script`).
- Same-session naming across processes (app and CLI at once): not serialised; documented limit. Names are rare, one-off actions, and a cross-process lock held over a possibly cloud-synced folder would stall forget. Forget and diarization are cross-process safe.
- Independent Claude Sonnet review (via rec-and-cc-7e), three Lows: file-lock depth is kept per (thread, voices folder); on Windows the lock polls `LK_NBLCK` with a backoff for up to 60 s and then raises a clean error; the naming osascript dialogs time out after 5 min so an abandoned chooser clears the guard.
- Later Cursor rounds: stale diarization/relabel runs after a forget neither name speakers nor delete newer voices; a relabel never overwrites names found on disk (CLI, menu or before a forget); prune runs outside the naming lock; the timeout-path write holds the naming lock; every store change takes the cross-process file lock; `write_final` fast path holds the naming lock.
- By design (no change): "Forget all voices…" stays enabled when `speaker_names` is off, so data can be deleted after opting out.
